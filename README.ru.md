# Light v0.2.9.11 — экспериментальное расширение динамического освещения Painkiller

Открытая библиотека для 32-битного PainEngine (DirectX 9), оригинального Painkiller и совместимых модификаций. Назначение — отображать дополнительный свет на геометрии, когда на меш влияет более четырёх источников.

При переполнении штатных четырёх источников библиотека формирует список освещения и воспроизводит его после `WorldMesh::Draw`. Световые проходы движка временно подавляются только при успешном построении такого списка. Меши с четырьмя и менее источниками используют штатную отрисовку. Работа новых конфигураций света в PainEditor и RoE требует проверки в игре.

## Конфигурация (`Light.ini`)

```ini
[Settings]
UnlockLights=1
MaxLights=128
ExtraPassesPerMesh=124
TimerSizeFix=1
LogLights=0
```

- `UnlockLights` — включить расширение света (`0` отключает световые перехваты).
- `MaxLights` — максимальный размер реестра источников для Entity (4–512), **не** число фактически отрисованных ламп.
- `ExtraPassesPerMesh` — бюджет проходов сверх базовых (0–512); `0` полностью отключает все хуки освещения.
- `TimerSizeFix` — независимое исправление таймера. Для проверки света можно поставить `0`.
- `LogLights` — агрегированная диагностика с интервалом примерно 5 секунд. `replayedMeshes` показывает, сколько мешей было перерисовано через новый путь, `replayedNative` / `replayedOverflow` — количество базовых и дополнительных источников в выбранных планах.

`Light.log` **перезаписывается один раз при запуске процесса** и хранится рядом с загруженной DLL.

## Сборка

Windows 10, Visual Studio 2022 C++ (Win32/x86), CMake. Запустите `build-win32.bat`. Он создаёт:

- `dist/vanilla/dinput8.dll` — для обычного Painkiller (файл `Light.ini` рядом).
- `dist/custom-exe/Light.dll` — для Custom EXE (файл `Light.ini` рядом).

Не загружайте обе библиотеки одновременно. Для редактора, если путь загрузки DLL содержит `Bin\\Editor\\DINPUT8.dll`, конфигурацию следует класть в `Bin\\Editor\\Light.ini`.

## Проверка

Сравните одну и ту же сцену с несколькими зелёными душами/факелами и одинаковыми настройками графики. На земле должен быть виден свет, а не только светящиеся частицы. Запустите сначала с `UnlockLights=0`, затем с `UnlockLights=1`, `ExtraPassesPerMesh=124`, `TimerSizeFix=0`. При неработающем свете включите `LogLights=1` и проверьте `replayedMeshes` / `replayedOverflow` в `Light.log`. `Installed lighting=1` **не** является доказательством успешной отрисовки.

**Ограничения:** дополнительные проходы могут быть дорогостоящими. Режим PKMDL, проекционный фонарик, взаимодействие с внутренним кэшем состояний D3Dev и полная совместимость RoE нуждаются в тестировании в реальном движке. Автоматические тесты проверяют планирование и последовательность вызовов на имитационном рендерере, но не изображение в PainEditor.


**Бюджет отрисовки:** `MaxLights` определяет ёмкость реестра, `ExtraPassesPerMesh` — количество *дополнительных вызовов рендера* на меш. Для 128 обычных ламп понадобится до 124 проходов. По умолчанию приоритет — видимость зарегистрированных ламп, а не FPS. При снижении бюджета до 16–32 часть света на перегруженных мешах неизбежно пропадёт. Пространственное отсечение света ещё не восстановлено.

## Подключение к Custom EXE

`Data/addons/Light.dll` требует **сборку исправленного `Painkiller.exe`** из
комплекта. EXE вызывает экспорт `Light_Initialize()` синхронно после загрузки
модуля, до инициализации Lua/мира. В отличие от `dinput8.dll`, эта сборка
не запускает поток установки хуков из `DllMain`. После установки
`dist/custom-exe/Light.dll` и `Light.ini` собери и замени EXE. В журнале
EXE ожидается `[Addons][Light] initialization=OK lightingActive=1`.
Это подтверждает хуки, но не доказывает корректность освещения в игре.
Не подключай одновременно Light.dll и вторую копию патча через `dinput8.dll`.
