# Light v0.2.1 — экспериментальная открытая библиотека динамического освещения

Библиотека для 32-битного Painkiller на DirectX 9, в том числе модификаций, использующих совместимые структуры оригинальной Engine.dll. **Поддержка всех сценариев проекционного освещения в игре пока не подтверждена.** Дополнительные световые проходы выполняются внутри `WorldMesh::Draw`.

## Конфигурация Light.ini

```ini
[Settings]
UnlockLights=1
MaxLights=128
ExtraPassesPerMesh=2
TimerSizeFix=1
LogLights=0
```

Только пять параметров:

- `UnlockLights`: включает перехватчики света. Для проверки ванильного освещения укажи `0`.
- `MaxLights`: вместимость реестра на один меш/Entity (4–512), **не** число гарантированно отрисованных источников.
- `ExtraPassesPerMesh`: максимум дополнительных вызовов `RenderLightPass` на меш (0–16). `0` полностью отключает установку световых хуков для строгого A/B-теста.
- `TimerSizeFix`: независимое исправление `GetCurrentTimeMS`; отключи `0` для изоляции проблем освещения.
- `LogLights`: сбор агрегированной диагностики каждые 5 секунд (выполняется только в расширенном пути).

## Сборка и запуск

Windows 10, Visual Studio 2022 Build Tools с C++ x86 и CMake:

```bat
build-win32.bat
```

- `dist/vanilla/dinput8.dll` и `Light.ini` — для оригинального Painkiller. Предварительно сохраните копии файлов игры. Если игра не загружает `dinput8.dll`, необходим иной согласованный механизм загрузки.
- `dist/custom-exe/Light.dll` и `Light.ini` — для кастомного EXE; экспорт `Light_Initialize` или совместимый `PKPatch_Initialize`.

Не ставьте обе DLL одновременно: это два способа загрузки одного и того же патча.

## Проверка дефекта факела

Сравни одни и те же положение и сцену: (A) **без DLL**, (B) `UnlockLights=0, ExtraPassesPerMesh=0, TimerSizeFix=0`, (C) `UnlockLights=1, ExtraPassesPerMesh=2, TimerSizeFix=0`. Перезапускай игру после изменения INI. Проверь фонарик, факел, подсветку геометрии и FPS.

Если дефект есть в (B), он не связан с дополнительным рендером и нужно отдельно исследовать хуки/таймер/структуры Engine.dll. Если только в (C), сбой связан с дополнительными проходами; пришли `Light.log` при `LogLights=1`.

Динамическая текстура фонарика, лучи с проекцией, PKMDL/анимированные объекты и иные специальные типы света сверх 4 источников пока **не поддержаны доказанно**. Отсутствие визуального бага ещё не доказывает увеличение лимита для этих объектов. Измерения в игре на реальном движке необходимы.
