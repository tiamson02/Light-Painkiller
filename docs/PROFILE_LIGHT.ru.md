# Профилирование динамического света Light

Сохранена работающая схема отрисовки v0.2.5. `MaxLights=128` — лимит зарегистрированных источников **на меш**, а не глобальный лимит карты. Даже 2 дополнительных прохода на меш могут стать дорогими, если десятки крупных мешей видимы одновременно. Эффекты душ (прозрачность/частицы) также расходуют видеоресурсы независимо от Light.

## Контрольная сцена

Зафиксируй положение камеры и количество душ (например, 75), отключи VSync и ограничения FPS, прогрей карту. Для честного сравнения целиком перезапускай игру между вариантами, оставляя `TimerSizeFix=0`, `LogLights=0`.

| Сценарий | UnlockLights | ExtraPassesPerMesh | Цель |
|---|---:|---:|---|
| A | 0 | 0 | Рендер без световых хуков Light |
| B | 1 | 1 | Цена одного дополнительного прохода на меш |
| C | 1 | 2 | Цена двух дополнительных проходов на меш |

В A сама DLL остаётся загруженной, но все световые хуки отсутствуют. Можно дополнительно сравнить с запуском без DLL, если загрузчик это допускает.

## Диагностика (отдельный запуск)

Для анализа включи `LogLights=1`, сохрани `UnlockLights=1`, `ExtraPassesPerMesh=2`, `TimerSizeFix=0`. Через несколько секунд скопируй **две последовательные группы строк `DIAG`** из `Light.log`. Лог перезаписывается при каждом запуске.

- `replayedMeshes`, `replayedOverflow`, `replaySingles`, `replayUberBatches`: накопленные отрисовки. Сравни приращение между замерами через 5 секунд.
- `overlap>8`, `overlap>16`, `overlap>32`, `maxSourcesOnMesh`: количество переполненных мешей с плотным перекрытием света.
- `sampled stockDraw`, `replayDraw`, `avgNativeUs`, `avgPrepUs`, `avgReplayUs`: выборочные **CPU-времена** на один Draw соответствующего типа (1 из 128). Небольшие выборки дают шумные результаты.
- `skippedUnsupported`, `skippedNoDevice`, `incompleteNative`: признаки неотрисованных дополнительных источников.

**Ограничение:** эти времена НЕ являются временем GPU. Часть GPU-нагрузки может проявляться задержками в D3D-вызовах, часть — только в GPU frametime. Если A уже даёт 10–20 FPS, ускорение реестра Light не решит проблему множества штатных источников и частиц. Если A заметно быстрее C и `avgReplayUs` велико или растут `replaySingles`/`replayUberBatches`, следующий этап — сокращение реальных световых проходов с корректным отсечением по области влияния. Не вводить покадровое пропускание источников, вызывающее мерцание.
