# Проверка Light v0.2.5 в PainEditor / Painkiller

Сборка: `build-win32.bat` (Visual Studio 2022, Win32). Библиотека из `dist/vanilla/dinput8.dll` должна лежать там, откуда её реально загружает процесс; конфигурация `Light.ini` — рядом с DLL. Для редактора это может быть `Bin\\Editor`.

Три независимых запуска в одной сцене с большим количеством душ и факелов:

| Режим | Настройки | Что проверить |
|---|---|---|
| A | Вообще без Light DLL | Является ли земля освещённой, FPS |
| B | `UnlockLights=0`, `ExtraPassesPerMesh=0`, `TimerSizeFix=0` | Изоляция загрузчика, без хуков |
| C | `UnlockLights=1`, `ExtraPassesPerMesh=2`, `TimerSizeFix=0` | Восстановление света на земле, FPS, поведение факелов |

Для теста C можно временно установить `LogLights=1` и смотреть `Light.log` (перезаписывается при каждом запуске). Ключевые счётчики:

- `add` — количество зарегистрированных источников;
- `overflowEligible` — количество Draw мешей, для которых зарегистрировано более четырёх источников;
- `replayedMeshes` — число мешей, реально прошедших новый алгоритм;
- `replayedOverflow` — общее количество дополнительных источников, выбранных для отрисовки;
- `replaySingles` / `replayUberLights` — реальные вызовы путей одиночного/группового света (включая базовые).

Если `add>0`, но `overflowEligible=0`, проверь, действительно ли источники света привязаны к одному `WorldMesh`, а не только отображаются как частицы или источники другого типа. Если `overflowEligible>0`, но `replayedMeshes=0`, тогда наш планировщик отклоняет сцену. Если `replayedOverflow>0`, но землю не освещает, искать ошибку в D3D render states / shader pass, а не в реестре.

Помните: эти проверки сами по себе не подтверждают отсутствие мерцания факелов и корректную проекцию фонарика. Нужен A/B по реальному изображению.
